# 运行环境说明（务必先读）

你现在跑在 **Docker 容器** 里，不是用户的个人电脑。容器是可丢弃的：重建之后，
除了被挂载出来的目录，你对文件系统做的改动全部消失。

## 你的自由区

`/workspace` 是你的工作区，**随便改**。它在宿主机上有对应的真实目录，你写的东西
用户能看到、能保留。日常任务、写文件、跑命令、装东西（在 workspace 里）都随意。

## 别动的两处：`.env` 和 `profiles/`

这两处不是"代码"，是**这台机器人的骨架**。改错不会报编译错误，会直接让机器人
起不来，而且症状往往很难查。

### `~/.dsh/profiles/qqbot/cordis.patch.yml`（以及 `profiles/web/` 下的同类文件）

这是 DSH 的插件树配置，决定"机器人由哪些部件组成、每个部件怎么配"。

改了会怎样：

- **写错 YAML**（缩进、冒号、缺引号）→ 启动阶段直接抛 `YAMLException`，qqbot
  进程退出，用户在 QQ 上永远等不到回复。
- **删了或改错关键条目**（`im-qqbot`、`llm-pi-ai`、`agent-default-model`、
  `model-fallback` 等）→ 要么机器人起不来，要么能起来但发不出消息。
- **改 `llm-pi-ai` 或 `agent-default-model`** → 这两个字段**以 Web 界面为准**。
  有个 `config-sync` 插件每 5 秒把 web profile 的值同步过来，你改完最多 5 秒
  就被覆盖回去。**看起来改了，其实等于没改**，很容易误导你自己和用户。
- **文件里还写着 `!!js` 之类的自定义标签**，不要用通用 YAML 工具重写整个文件，
  会破坏这些标签。

### `.env`（项目根目录，宿主机上）

容器的启动参数：QQ 凭据、端口、模型默认值、群聊门控等。

改了会怎样：

- **改了不重启不生效**。而重启容器会中断正在进行的对话。
- **改 QQ 凭据** → 机器人掉线，得重新扫码绑定。
- **改模型默认值** → 和 Web 冲突，同样会被同步逻辑盖掉。
- 这个文件在宿主机上、且被 `.gitignore` 排除，改坏了用户可能连自己原来填了什么都找不回。

## 确实需要改的时候怎么办

**不要自己动手改，告诉用户。**

说清楚三件事就行：

1. 你想改哪个文件、哪一项
2. 为什么要改（解决什么问题）
3. 改完会有什么影响（要不要重启、会不会掉线）

让用户决定，由用户在 Web 界面（`http://<host>:8766` 的设置页）或宿主机上改。

如果用户明确说"你帮我改"，再改，并且：改之前先备份同目录的副本，
改完立刻验证文件仍是合法 YAML，并告诉用户需要重启才能生效。

## 一个已经踩过的坑

曾经为了配置记忆库的语言，连续调了十几次工具去改 `profiles/` 下的配置。
结果是：那一刻确实写进去了，但既没有即时生效，配置内容也和 Web 界面的值冲突，
排查了很久。**这类改动不值得自己动手。**

# 优先级

以上是环境约束，不是产品需求。用户当前的直接指令永远优先；如果用户的指令和
这里冲突，照用户说的做，但要先提醒他可能的后果。
